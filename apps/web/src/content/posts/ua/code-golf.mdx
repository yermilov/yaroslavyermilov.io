колись здається в 2018 році ми придумали ідеальну розвагу для нашого стенду на конференції jeeconf

гра називалася код-гольф і правила були дуже прості: напишіть найменшу програму (щоб було простіше рахувати, домовляємося що пробіли/ньюлайни не рахуємо) яка виведе на екран наступний текст:

```
JDK 1.0 was released in January 1996
JDK 1.1 was released in February 1997
JDK 1.2 was released in December 1998
...
JDK 41 will be released in September 2033
JDK 42 will be released in March 2034
```

учасників було десь тридцять і троє з них потім прийшли до нас працювати, астрономічна конверсія на рівні 10% у порівнянні з типовими розвагами на конференціях

## Спробуйте і ви

звичайно в 2026 році ніхто не буде писати код руками, тому скидайте промпт своєму улюбленому агенту:

```
read the code golf task described in github gist
yermilov/a764a182d63e0fa261104064ca6ff0e3
try to solve it. do no harm, just write and run the code
```

повні правила і всі 43 рядки таргету лежать [у тому ж гісті](https://gist.github.com/yermilov/a764a182d63e0fa261104064ca6ff0e3). перше що агент спитає вас — як саме до цього підходити

## Модель це не точка, а діапазон

кожна модель має ручку ефорту - скільки токенів їй дозволено спалити на одну відповідь. крутити ефорт часто вигідніше ніж міняти модель, а на fable навіть низький ефорт часто обганяє xhigh попередніх моделей. тобто модель це не точка на шкалі, а діапазон, і діапазони сусідніх моделей перетинаються

## Дві техніки

в реальному світі звичайно ніхто не дає моделі задачу і одразу очікує правильного розв'язку. записуйте дві найпростіші і найефективніші техніки

перша: спочатку досліди

```
before you write any code, research the techniques that make a program
like this shorter. only then implement
```

друга: ітеруй і валідуй

```
keep shrinking it until you run out of ideas
```

модель на слабшому ефорті майже завжди обганяє себе ж на сильнішому ван-шотом. медіанний виграш - 30%, це 89 символів

## Найкоротше що я бачив

у 2018 році коли ми давали цю задачу живим людям на конференції двоє учасників підловили нас на умові по пробілам і закодували текст який треба вивести за їх допомогою. найкоротше що я бачив виглядає так:

```ruby
"<131 756 пробілів і 1 672 таби>".scan(/ +/){putc$&.size}
```

зараз до цього додумалися чотири моделі з семи. найкраще fable - у ван-шоті, без жодної підказки, з першої спроби. решта три це все сімейство gpt-5.6, але тільки якщо на xhigh попросити спершу дослідити тему або ітерувати

у 2018 до цього додумалися двоє з тридцяти. у 2026 - четверо з семи
